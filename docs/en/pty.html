Pty — PTY Wrapper for Go

Overview

The pty package provides a Go wrapper around pseudoterminals (PTYs) for interacting with subprocesses in a terminal-like environment. It integrates with the Bubble Tea framework for reactive terminal applications.

The package uses:

  • os/exec for spawning child processes
  • github.com/creack/pty for PTY handling
  • github.com/charmbracelet/bubbletea for Tea message passing

Types

Pty

type Pty struct {
    cmd    *exec.Cmd
    ptmx   *os.File
    reader *bufio.Reader
    Output chan []byte
    Errors chan error
    done   chan struct{}
}

Fields:

  • cmd: The underlying exec.Cmd for the spawned process
  • ptmx: The pseudoterminal master file descriptor
  • reader: Buffered reader for PTY output
  • Output: Channel receiving output data chunks from the PTY
  • Errors: Channel for error messages
  • done: Done channel for graceful shutdown

PtyOutputMsg

type PtyOutputMsg struct {
    SessionID string
    Data      []byte

Message sent when new data arrives from the PTY output channel.

PtyExitMsg

type PtyExitMsg struct {

    Err       error

Message sent when the PTY process exits with an error or EOF.

Resize(rows, cols int) error

Resizes the PTY and signals the child process about the change. This is used to update the terminal window size.

Parameters:

  • rows: Number of rows
  • cols: Number of columns

Returns:

  • error: Error if the PTY is closed or resize fails

Implementation Details:

  • Rate-limited to avoid rapid consecutive resize signals (50ms cooldown)
  • Sends SYSCALL.SIGWINCH to the child process to notify it of the resize

Internal Implementation

readLoop

A goroutine that continuously reads from the PTY's file descriptor and forwards output to the Output channel or errors to the Errors channel.

Behavior:

  • Reads 4KB buffers from the PTY
  • Handles terminal escape sequences:
    • \x1b[6n (SR - cursor position report): Sends \x1b[1;1R (RIS - reset)
    • \x1b[5n (PR - paste report): Sends \x1b[0n (ESC)
  • Forwards data to the Output channel
  • Forwards errors (excluding EOF) to the Errors channel
  • Respects the done channel for graceful shutdown

Usage Examples

Basic PTY Usage

package main

import (
    "fmt"
    "os"
    portalis "path/to/portalis"
)
func main() {
    pty, err := portalis.Spawn("bash", []string{})
    if err != nil {
        fmt.Println("Failed to spawn PTY:", err)
        return
    }
    defer pty.Close()

    // Send a command
    _, _ = fmt.Fprint(pty.Output, "echo hello\n")

    // Read output
    for {
        select {
        case data := => pty.Output:
            fmt.Println("Output:", string(data))
        case err := => pty.Errors:
            fmt.Println("Error:", err)
        }
    }
}

Bubble Tea Integration

package main

import (
    "fmt"
    portalis "path/to/portalis"
    tea "github.com/charmbracelet/bubbletea"
)
type model struct {
    pty    *pty.Pty
    output []byte
    error  error
}

func (m model) Init() tea.Cmd {
    return func() tea.Msg {
        return portalis.Listen("session-1")
    }
}

func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(interface){
    case portalis.PtyOutputMsg:
        m.output = append(m.output, msg.Data)
        return m, nil

    case portalis.PtyExitMsg:
        m.error = msg.Err
        return m, nil

    case tea.KeyEnter:
        if m.pty != nil {
            return m, portalis.SendBytes(m.pty, []byte("\n"))
        }
    case tea.KeyCtrlC:
        return tea.Quit(), nil
    }
    return m, nil
}

func (m model) View() string {
    if m.error != nil {
        return "Error: " + m.error.Error()
    }
    return "Output: " + string(m.output)
}

Important Notes

  • Always call Close(): Make sure to close the PTY when done to free resources
  • Handle errors: Check the Errors channel for process termination signals
  • Environment variables: Use SpawnInDir with env parameters to set custom environment
  • Resize handling: The Resize method is rate-limited to prevent rapid consecutive resize signals
  • Terminal escape sequences: The readLoop handles certain escape sequences and responds appropriately
