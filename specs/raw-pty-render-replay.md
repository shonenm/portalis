# Диагностика рендера через raw PTY replay

## Контекст

Визуальные исправления не устранили артефакты, а wide-cell изменение ухудшило отображение. Скриншот показывает только итоговое повреждение и не позволяет определить, какая входная ANSI/Unicode-последовательность обработана неверно. Нужна точная запись исходного PTY-потока и детерминированное повторное воспроизведение.

## Цель

Записать входные PTY-байты проблемной сессии без преобразований, воспроизвести их в unit/integration-тесте Portalis и исправить конкретную ошибку parser/screen renderer.

## Что изменится

1. `pty.go` — опциональная бинарная запись прочитанных PTY-байтов при заданном env.
2. `ansi_test.go` или новый replay-тест — детерминированная подача trace в Parser.
3. `ansi.go`/`screen.go` — исправление, определённое replay-тестом.

## Детали реализации

1. Env `PORTALIS_RAW_TRACE` задаёт путь бинарного trace; без env поведение и производительность не меняются.
2. Каждый chunk записывается в trace до отправки в Bubble Tea.
3. После воспроизведения пользователь закрывает Automata, trace читается тестом как единый упорядоченный поток.
4. Тест фиксирует строки status bar, видимую ширину и отсутствие orphan ANSI/Unicode-ячеек.
5. Исправление делается только после доказанного расхождения в replay.

## Критерии приёмки

- [ ] При пустом `PORTALIS_RAW_TRACE` нет файловых операций.
- [ ] Trace сохраняет исходные PTY-байты в правильном порядке.
- [ ] Replay стабильно воспроизводит текущий артефакт.
- [ ] Исправление устраняет артефакт в replay-тесте.
- [ ] Все тесты Portalis и Automata проходят.
- [ ] Automata пересобрана.
